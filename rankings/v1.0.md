# model-bench v1.0

**发布日期**：2026-10-22
**用例**：31 个（L0 7 / L1 10 / L2 6 / L3 8）
**权重**：L0 10 / L1 20 / L2 40 / L3 25 / 成本 5
**测试床**：`model-bench-mockrepo` @ `a13ff60`
**配置版本**：`bench.config.jsonc` → `bench.version = 1.0.0`

| 1 | Claude Sonnet 5.5 | `flash-sonnet` | **95.0** | 100.0 | 100.0 | 100.0 | 100.0 | 31/31 |

## 分层分解

| 层 | 权重 | 考什么 | 两模型差距 |
|---|---|---|---|
| L0 通道 | 10 | 连通、精确回显、语言纪律、权限边界、不瞎编 | 无 |
| L1 单点 | 20 | 定位、最小编辑、取证、定性纪律、代码考古 | 无 |
| L2 流水线 | 40 | SOP 闭环、测试报告、版本同步、审查收敛、回归、跨会话继承 | 无 |
| L3 Harness | 25 | 扇出并行、二层嵌套、汇聚、多轮记忆、卡死介入、权限、工具恢复、热切换 | **14.0 分** |

## 唯一失分项

`l3-01`：并行完成三个独立修复（前端按钮、NEW 角标注册、BFF 素材文案）。

| 模型 | 行为 |
|---|---|
| Sonnet 5.5 | 3 个 subagent，3 个文件全部改对 |
| Opus 5.5 | 2 个 subagent，只改 2 个文件，**连续两次都漏掉 `new_badge.go`** |

`new_badge.go` 的任务只是往注册表里加一行 key。Opus 还顺手改了未被要求的
`RoomConfirmListPanel.tsx`，却漏掉这个配置类小任务，说明并行扇出时它优先做有逻辑的任务。

## 成本

| 模型 | 输入 token | 输出 token | 总时长 |
|---|---|---|---|
| Sonnet 5.5 | 7,069,163 | 61,233 | 28m |
| Opus 5.5 | 8,113,891 | 65,111 | 34m |

Opus 多花 15% token、21% 时间，得分低 3.5 分。

## 复现

```bash
git clone --recursive https://github.com/hcfw007/model-bench.git
cd model-bench
git checkout v1.0.0
cd mockrepo && git checkout a13ff60 && cd ..
node runners/run-bench.ts --models pro-opus,flash-sonnet
```

## 已知局限

- 样本只有 2 个模型、各跑 1 次，没有重复实验，无法给出置信区间
- 31 个用例中 30 个被两个模型同时通过，区分度集中在 `l3-01`
- `l3-04` 实测未触发 compaction，只覆盖跨轮记忆
