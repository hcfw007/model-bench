# Judges

当前 32 个 case **全部使用硬断言**，不需要 LLM judge。

原因：这套基准刻意把「可判」的边界画在产物、轨迹、文本证据上。
凡是必须靠人主观打分的任务（例如「这个方案好不好」），都不进基准，
因为那类题无法用于跨模型复现比较。

## 什么时候才需要加 LLM judge

只有一种情况：需要评价**产物质量而非存在性**，例如

- 修复说明是否让一个没看过上下文的人能 review
- 测试报告里的 FAIL 证据链是否自洽
- 计划文档是否遗漏了已知约束

## 加 judge 的约束

1. judge 必须是**二元或三档**（pass / partial / fail），不给连续分。连续分不可复现。
2. judge 的 prompt 必须内嵌 `gold` 字段作为唯一参照，不允许它自由发挥标准。
3. judge 结果只作为 `partial` 计入，**不能把硬断言失败翻成通过**。
4. judge 使用的模型不能是参评模型本身。

## 当前用 gold 替代 judge 的 case

`l2-01` / `l2-02` / `l2-05` 的质量要求已经用
`fileContains` + 隐藏测试 + `textMatch` 覆盖，故意不引入 judge，
以保证同一 case 在不同模型上的分数完全可比。
