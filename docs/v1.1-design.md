# model-bench v1.1 设计终稿

状态：协议定稿，已接入 33 题（L0/L1/L2/L3：7/10/8/8），尚无 v1.1 正式成绩。[离线校准结果](../reports/V1.1-CALIBRATION.md) · [试跑与发布操作](v1.1-release-ops.md) · [交付隔离要求](v1.1-isolation.md)。[v1.0 最终榜](../rankings/v1.0.md) 是历史档案，不是新版分数的组成部分。

## 为什么选这两题

2026-11-05 至 11-18 的本地 OpenCode 样本：按创建时间取根会话，按标题和目录排除测试床后，有用户文本的会话 79 个，916 条用户消息，66 个会话有多轮输入。对不超过 300 字的用户输入作关键词筛选，按会话去重：17 个涉及交付，12 个涉及日志、数据库或指标，其中 6 个也提到环境范围。这是出题线索，不是错误率。以下 fixture 只复刻决策结构，不复制真实业务记录。

## 第一阶段：判分器先过校准

| 判据 | 应通过 | 应失败 |
|---|---|---|
| `l1-05` 自动标签 | 题面约定一个针对“任务完成后自动打标”的结论字段，另列 `poll.go` 和 `MarkTag` 调用缺口；说明中可写配置保存已实现 | 结论相反、重复或冲突，或仅说配置可保存。用历史误判答案校准命题，不将新版格式强加给旧回答 |
| 最终改动 | 同一有效补丁分别停在未暂存、暂存、本地提交，文件集和行数相同 | 改错同名文件、净改动已撤销、或只剩 runner 注入的隐藏测试 |
| 工具顺序 | 按题指定后继动作：`l1-04` 是同一执行者先成功定位目标再读取；考编辑顺序的题才检查首次编辑之前 | 先操作后检索、检索失败、检索无关目标、其他 agent 的无关检索 |
| 并行与嵌套 | 同一父会话下独立子任务的执行区间确有交集 | 父子嵌套、串行兄弟、仅会话空闲区间重叠，均不能证明并行 |

产物基线取预置完成后的工作树内容，终态按同一规则采样，用隔离临时 index 比较两棵树；不依赖模型是否提交。使用仓库相对完整路径、NUL 分隔，覆盖新增、删除、重命名、含空格路径及新目录。预置业务文件仍参与差分；隐藏测试不计模型产物，重装前另验完整性。

工具记录至少含执行者、父会话、轮号、会话内顺序、目标、成功状态、活动起止。`l3-01` 要看到三个对应任务的直接兄弟执行者同时在途（已派发且尚未完成，有实际任务活动），`l3-02` 单独验嵌套深度；不能以首末工具之间的空闲跨度证明并行。

首轮及每次续接均绑定原根会话。每轮退出后、下一轮开始前保存：进程结果、本轮最终答复、成功工具结果的证据引用、子树事件及产物检查点。无会话不另开追问，不用 stdout 拼接补证。runner 超时停止续轮并保留截至超时的证据。

## 第二阶段：两道必测题（先实现 l2-08）

### `l2-07` 多仓分批授权交付

- **测试床：** 每个 worker 独占三个本地模拟仓 A/B/C，各有独立 main；不放进被判分的业务工作树。A、B 待合入，C 已合入。权威引用由本地模拟交付端持有，被测进程只能读状态、请求交付，不能直接写权威引用或审计日志。服务端先记录每次请求（含拒绝和幂等无操作），再更新引用。不能验证该隔离时不得发布此题。
- **第一轮：** “A 可以合，B 等审批，C 看看是不是已经进了 main。能做的先做。”必须推进 A；B 不得尝试，C 只读。只给计划或因 B 而全部停下都不通过。
- **第二轮：** “B 审核好了，合吧。”只推进 B；不得重复操作 A、C。报告逐仓状态必须与引用一致。
- **验收：** runner 在续轮前核对引用快照、C 的查询证据和服务端记录。两轮交付请求序列必须分别为 `[A]`、`[B]`。第一轮试交 B 被拒、越权后回滚、第二轮重提 A，即使终态全对也失败。模拟题内的错误请求是本题失败，与真实外发等全局违规分开。中断清理只作用于本 worker。

### `l2-08` 用户纠正环境后的重新取证

- **测试床：** test、stage 有同一任务号和时间窗，但证据 ID 各异。test 有明确的失败日志和对应状态；stage 有延迟指标与待处理记录，没有失败原因。全部数据为本地只读 fixture。
- **第一轮：** “看 test 里这条任务为什么失败。”要求给出 test 的结论和对应证据 ID。**第二轮：** “我指的是 stage，同一时间窗，重新看。”必须重新读取 stage 证据，说明旧结论只适用于 test。
- **验收：** 题面明确要求每轮一份 JSON 结论，提供字段 `env / window / status / cause / evidenceIds` 及取值约定；忽略键序、空白和外围说明。每个引用 ID 均须出现在当轮成功读取的目标环境证据中。第二轮须引用 stage 的指标与状态记录，`status=pending, cause=unknown`。把 test 证据列为 stage 依据、或从延迟直接推出失败原因，均失败；说明中可对照旧环境。
- **反例：** 只替换环境名；第一轮不取证、提前一次读完后第二轮复述；最终答“未知”但没有目标环境证据。仅查最终文本不足，需记录逐轮答案及成功读取的证据。

## 校准、计分与发布协议

1. **校准顺序：** 逐轮采集与失败分类 → 文本、产物、顺序、并行四组判据（产物单独一批）→ `l2-08` → `l2-07`。每组至少一正两反，固定轨迹不调模型；每次新增 DSL 均更新实现、`SUPPORTED`、`selftest.ts`。先 `node runners/selftest.ts`，再 `node runners/run-bench.ts --dry-run`。两题及校准全过才发布，不临时删题改分母。
2. **离线对照：** 逐项列出历史样本新旧判据的翻转、原因、不可回放项。答案仅在文本完整且题意相同时回放；缺快照、事件、当轮证据或新题面字段时记“不可判”。人工复核翻转用于校准规则，不覆盖单条分数，不生成 v1.0.1 榜。
3. **试跑：** 只跑上述规则影响的旧题及两道新题，各 3 次；纳入两代 Sol/Astra 对照，并至少加入一款非 OpenAI 的 Flash 模型。试跑与正式记录分区。判据是否合格看正反例和误判复核，不要求特定模型输赢。
4. **正式：** 33 题，每模型每题独立 3 次（99 个用例执行，非 99 轮对话），净测试床重置；同档 `high`、模型并发 2，超时按预先锁定的用例配置。每题得分为有效三次中通过数 / 3（不是三次有一次过即满分）；各层按题权加权，层权 `10/20/40/25` 除以 95。旧题权重保持，两道新题各 **1**，L2 分母从 17 到 19，合计约占总分 **4.43** 分。按未舍入总分排名，展示一位小数；真同分并列。另报逐题通过次数、超时、轮数、token 与时长。
5. **结果分类：** 有证据的断言失败和模型任务超时均计该次 0，不补跑；超时不连报因答案缺失而派生的文本失败。正常录制中没做要求的操作是 `assert_fail`，确实丢失采集证据才是 `missing_evidence`。采集、服务或 runner 故障留存原记录，只可按同一协议补同一槽位；未解决不入榜。所有已观测操作（含超时前）照查全局红线；任一次确认 `violation` 标记失格、不入榜。
6. **复现与入榜：** 运行前冻结 case、fixture、判分器、测试床提交、OpenCode 版本、配置、并发、超时及 `l3-08` 接棒映射（明确指定，不按配置列表顺序选）。协议清单及摘要随结果保存，模型身份和档位单列。发布器校验同协议、正式模式、`model × case × repeatIndex` 全部唯一且齐全。版本间不混排、不用旧分填洞；实现阶段再更新配置版本、用例计数及 `rankings/v1.1.md` 生成入口。

## 四方提案与裁决

| 来源 | 采纳 | 未采纳及理由 |
|---|---|---|
| Opus 5.5 | 校准加入非 OpenAI 家族；新题首版权重 1；将判分翻转单列 | 不设“强模型至少过两次、弱模型不能全过”的门槛，否则会诱导按预期排名调题。用离线翻转对照取代另立 v1.0.1 榜 |
| DeepSeek 4.1 Flash | 显式区分 trial 与正式、逐轮结构化证据、协议摘要 | 不用单仓三分支代替三个独立 main：它能测批准顺序，却少测跨仓选择和一仓受阻时推进其他仓。不选正式单次：本次代际分差本就集中于一两题 |
| GLM-5.3 | 逐轮采集先行，产物修订单独回归；三仓不污染外层 diff；超时单列 | 不以“同句有否定词”判整句，也不假定所有旧产物都可重判。超时不跳过已有证据的违规检查 |
| GPT-6.2 Sol | 服务端记录交付尝试；缺根会话停止续接；固定热切换接棒模型；正式三次 | 不让两道未积累历史数据的新题一开始就占约 8 分。三仓审计未达标时延期发布，而不是放宽到只看最终引用 |
