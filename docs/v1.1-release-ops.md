# v1.1 发布前验收

发布器只接受已完成的正式主运行和同一冻结内容的验收材料。`protocol.lock.json` 的运行摘要包含模式、并发、重复次数和实际题集；验收使用另一个**内容摘要**，覆盖冻结文件、配置、mockrepo 提交、OpenCode 版本、平台、接棒设置及交付隔离状态，不比较不同模式的运行摘要。

正式锁定、正式执行和验收试跑要求已部署的 [rootless Podman 后端](v1.1-isolation.md)。没有后端的环境只允许普通试跑；预检失败不会调用模型。`--mode formal --dry-run` 只离线校验题集和参数，不做宿主预检，也不产生正式锁。不要以 root 运行或为试跑修改主机权限。

## 1. 只锁定协议，不调模型

```sh
node runners/run-bench.ts --mode formal --lock-only --out reports/v11-plan --isolation-config /path/to/backend.json
node runners/protocol-release.ts calibrate reports/v11-plan reports/v11-evidence
node runners/protocol-release.ts trial-args reports/v11-plan
```

`--lock-only` 对所选模型执行无模型隔离预检并保存锁。锁分别记录普通用例的宿主 OpenCode 版本、l2-07 的镜像引用及镜像 ID、容器程序路径与实际 `--version` 值、Podman 版本。容器程序不从宿主路径读取。`calibrate` 验证当前快照与锁一致后，依次离线运行 `selftest`、正式 `--dry-run`，保存日志与退出码。

`trial-args` 只输出参数。改题集从冻结题目提取：产物差分、隐藏测试、指定工具顺序、分支/嵌套子任务、逐轮编辑限制、接棒、自动打标结论的新判据，以及两道场景题。不要手工少跑/多跑。两代对照是 `gpt-6.1-sol` / `gpt-6-astra` 与 `gpt-6.2-sol` / `gpt-6.2-astra`，再选一款配置已登记的非 OpenAI Flash，全部 `high`。

获明确试跑授权后，将该参数串传给 `run-bench.ts`，替换 Flash 和隔离配置占位符，另加 `--out reports/v11-trial`。验收试跑必须显式选择与正式协议相同的隔离后端；未选择隔离的普通试跑不能用于发布。验收试跑会调用真实模型，之后把结果收进验收目录：

```sh
node runners/protocol-release.ts trial reports/v11-plan reports/v11-evidence reports/v11-trial
```

## 2. 附上人工验收原件

- `replay.md` 逐项记录历史样本、新旧判据、翻转原因和不可回放项，并引用固定正反例。`review-description.json` 写 `reviewer` 字符串和 `groups` 对象；键为 `turns-outcomes`、`text`、`artifacts`、`order`、`parallel`、`l2-08`、`l2-07`；每项写实际执行的 `{"positive": 1, "negative": 2}` 或更高实测数。
- `isolation.log` 保存独立验收原始结果：实际模型权限主体、权威端权限边界、允许请求和拒绝证据、引用与日志检查以及 worker 清理范围。`isolation-description.json` 写 `reviewer`、与锁一致的 `platform`（例如 `linux/x64`）及 `checks`；全部经过实测再填 `true`：`separate-authority`、`model-cannot-write-refs`、`model-cannot-write-audit`、`model-cannot-control-authority`、`request-audited-before-update`、`worker-local-cleanup`。

```sh
node runners/protocol-release.ts review reports/v11-plan reports/v11-evidence replay.md review-description.json
node runners/protocol-release.ts isolation reports/v11-plan reports/v11-evidence isolation.log isolation-description.json
node runners/protocol-release.ts verify reports/v11-plan reports/v11-evidence
```

人工凭证是维护者对实测的具名核验，不是沙箱证明或数字签名；CLI 还会按模型检查预检及 `l2-07` 的实际轮次证明。首轮实际超时允许只有一个有效检查点；普通结算需要两个。当前旧凭证**即使齐全也不能发布**；后端更换后必须重新冻结、校准、试跑和验收。

## 3. 正式与补槽

正式运行需另获授权；完成后如有 `error` / `missing_evidence`，按原协议补槽并合并。正常断言失败、超时或违规不得替换。旧尝试和两次退出状态留在报告中；只根据核实且已补齐的槽位重新判定成绩资格。

```sh
node runners/run-bench.ts --mode formal --repair reports/v11-formal --out reports/v11-repair --isolation-config /path/to/backend.json
node runners/merge-results.ts reports/v11-formal reports/v11-repair
node runners/sync-rankings.ts reports/v11-formal --version v1.1 --evidence reports/v11-evidence
```

未指定 `--evidence` 时读取正式报告下的 `release-evidence/`。所有入榜条件检查通过后才改动两个 README 的标准 `RANKING` 区块和 `rankings/v1.1.md`；v1.0 一律只读。
